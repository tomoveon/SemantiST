# 论文方向综合建议

2026-10-18（修订版）

方向的宏观表述以[研究方向](../research_direction_zh.md)为准，分阶段的工作见[计划书](../research_plan_zh.md)。本文保留方法细节、新颖性边界和文献对比。

本文综合 `docs/improvement/` 下的四份材料（静默＋缓慢、静默、online change、OSCAT 长时运行数值候选普查）、`docs/top_venue_review_20261018_zh.md`（下称“评审”），以及 GPT 对本文初版的审查意见，给出一条推荐主线。

**结论。** 方向保持不变：主线是**静默数值缺陷的后果判定**，评审中的保真度测量并入，作为动机和第一组结果。但核心问题要收紧为：

> 在一个固定的 PLC 目标语义下，如何区分有意的模运算行为与会跨扫描周期影响控制决策的数值错误，并给出能在原生平台上重放的证据？

这仍是一个**待验证的研究假设**。新颖性不能靠“把影子执行或信息流过滤搬到 ST 上”，必须落在 PLC 带来的具体障碍和解决它的机制上（第 4 节）。下一步应先证明判据能判对，而不是先把双执行系统做大。online change 留作第二篇，或作为主线受阻时的转向。

## 2. 主线论点

**表述（存在性，而非普遍性）：** 宿主机重编译后的崩溃，不能可靠证明原生 PLC 上存在对应缺陷；原生 PLC 上的控制错误，也可能没有任何崩溃信号。

两个方向的证据现状：

| 方向 | 已有证据 | 状态 |
| --- | --- | --- |
| 崩溃不能证明原生缺陷 | OSCAT 重放分类；RuSTy 标准库的 UTF-8 panic 在 CODESYS 中没有对应代码 | 要按独立根因重新统计并做 CODESYS 确认 |
| 原生控制错误可能不崩溃 | REAL_TO_STRF 在 CODESYS 上输出 `--695...`；INC 的 `MOD 0` 在 Control Win V3 x64 上静默返回 0，调用方循环不退出，看门狗停机 | 只是存在性的例子，普遍程度由 RQ2 测量 |

保留合并的理由：

- **对冲风险。** 第一个方向的数据已经基本在手；即使后果判定的结果偏弱，论文也有一个确定的测量结果。
- **平台语义两头都用。** 同一份平台配置既能消掉假阳性，又能暴露只在目标平台上出现的静默行为。

安全意义要靠完整的证据链，不能靠“类型合法”跳过（第 3.7 节）。

## 3. 方法

### 3.1 第一版范围

- 只覆盖确定性、单任务、不含指针和原始内存操作的数值类 FUNCTION/FB：不使用 `REF`、`ADR`、`POINTER`、`MEMCPY`，不依赖 `SIZEOF`，不把字节数组当原始内存用。
- 遇到不支持的语义，明确退出比较并记为“不支持”，不做猜测；支持率要公开报告。
- 空间内存错误（越界读写，包括实例内越界）不进主线。现有的 ArrayBounds 违例检测继续保留，但只作为普通违例报告；判断它们的后果需要对象边界、受损对象和应用性质等另一套证据，可作为后续工作。

### 3.2 平台语义先行

先承诺一个具体配置：运行时版本、目标架构、编译选项（包括 STRING 用 Latin-1 还是 UTF-8）、库版本。建议从你笔记中的环境起步：CODESYS V3.5 SP21 Patch 3、Control Win V3 x64、oscat_basic 3.3.5.0。每个条目都要配一个与该运行时的差分测试：

| 条目 | 要校准的内容 | 影响 |
| --- | --- | --- |
| 中间结果宽度 | x64 上中间结果为 64 位，只在赋值或转换时截断 | 现有 IntegerOverflow 谓词按表达式类型的位宽判断，对 `IF a + b > LIMIT` 这类不赋值的中间运算，相对该配置是误报；判断点要移到赋值和转换处 |
| 除零与取模零 | 在该配置上实测 DIV、MOD 对零的结果 | INC、INC2 的行为 |
| TIME 与时钟 | TIME 为 32 位毫秒；T_PLC_MS 的回绕方式 | 输入合法域；A1 写法 |
| REAL 转整数 | 越界时的结果 | REAL_TO_STRF |
| STRING | 编码设置；函数在边界上的行为 | UTF-8 panic 类伪影 |

### 3.3 规定的参考语义

参考执行按事先规定的规则计算，不声称代表开发者意图：

- 隐式算术（+ − ×）与隐式转换：用无界整数，或带检查的扩展精度计算；超出支持范围就退出比较。
- 显式整数窄化、位运算、移位：两边都保持模语义。
- REAL 转整数：参考执行保留精确整数值，后续整数运算继续在无界整数上进行，转字符串时输出精确值。
- 时钟：参考执行使用不回绕的时间 τ，实际执行使用 τ mod 2^w。

这是一套启发式规则。两个在目标平台上行为等价的程序，可能只因为一个用赋值转换、另一个用显式转换函数，就得到不同的判断。所以评测要包含“等价改写对”（第 6 节），把这种不一致测出来并报告。已知漏报（例如 FRMP_B 把 `SHL(..., 8)` 当乘以 256 用）用开发集真值来量化。

### 3.4 按关系比较，而不是按值比较

实际执行与参考执行的持久状态，按类型定义对应关系后再比较：

- 被规定为模运算的量（时钟派生值、显式按模使用的计数）：模 2^w 相等即视为等价；
- 其余量：要求相等。

只有当输出或分支决策出现偏离时，才进入第二层结论。这样 A1 写法在时钟回绕后不会被误判，而累计量回绕导致报警失效（《静默》中的写法 B）会被报告。

### 3.5 用干预重放做跨周期因果归因（候选核心机制）

两份执行的差异只是一条证据时间线，不能说明因果。例如同一周期里 a 和 b 都溢出，下一周期只有 b 参与报警判断：两边 a、b 都不同，随后 alarm 也不同，但这并不能说明是 a 造成的。全程序同时改变所有算术，还可能出现误差抵消、状态被覆盖、参考执行走上不同路径等情况。

因此对每个出现第二层偏离的输入：

1. 把违例事件标识为（周期，位点）；
2. 逐个或成组地只修正某些事件、其余保持平台语义，重放并观察后果是否消失；
3. 得到“哪个事件对后果是必要的”，以及它经过哪些持久变量、在第几个周期影响输出。

**要比较的前作：** Zeller 的 Isolating Cause-Effect Chains（FSE'02）用 Delta Debugging 在成功运行和失败运行的状态之间缩小差异，得出因果链，机制上很接近。本文要说明的差别是：对照的一方是规定的参考语义，而不是另一次成功运行；事件以扫描周期为单位，状态按关系比较；而且要处理正常模运算。这能否构成足够的新颖性，需要原型结果来回答。

**成本：** 只对出现偏离的输入做，但成本要计入总预算。

### 3.6 三层结论

| 层次 | 能支持的结论 | 报告时的叫法 |
| --- | --- | --- |
| 1 | 发生了有限精度事件（回绕、截断、除零等） | 违例 |
| 2 | 该事件经归因后，在参考规则下造成了输出或分支偏离 | 可观察偏离 |
| 3 | 违反了契约或控制性质，或经人工、原生平台独立确认 | 缺陷；再单独判断安全影响 |

只有第三层能叫“有害”。

### 3.7 安全证据链

一个案例要升级为安全问题，需要完整的链条：

1. 威胁模型中的攻击者能影响的输入（不仅是“通过 Modbus 暴露”，还要说明攻击者为何有权写它）；
2. 满足应用约束的扫描历史（应用允许的范围，而不仅是类型或平台取值域）；
3. 原生平台上的错误行为；
4. 被违反的具体联锁、报警或控制性质。

REAL_TO_STRF 可以作为数值缺陷的例子，但不能作为安全主案例，除非能在真实调用方上展示影响。人为构造一个脆弱的调用方，不能证明原库存在现实的攻击路径。

## 4. 相关工作与新颖性边界

| 工作 | 已经做到的 | 对本文的含义 |
| --- | --- | --- |
| Dietz 等，ICSE'12 | 系统测量 C/C++ 整数溢出，发现有意回绕非常普遍 | “违例不等于缺陷”的出处 |
| IntFlow，ACSAC'14 | 按不可信来源过滤；Sensitive Operations 模式只在整数错误流入敏感汇点时报告 | “传播到敏感位置才报告”不是新贡献 |
| Herbgrind，PLDI'18 | 高精度影子执行，只报告影响输出或控制流的浮点误差；含 PID 控制器跨循环累加的案例 | “与高精度对照”“跨迭代累积”都不是新贡献 |
| Zeller，FSE'02 | 在两次运行的状态差异上隔离因果链 | 第 3.5 节机制的直接前作 |
| K-ST | ST 的可执行形式语义，并与 CODESYS 做差分 | 目标对象不同，但平台语义的建模与验证方法必须比较，不能说“不撞” |
| ICSQuartz、LogicFuzz、Ta'veren、ST-Checker 等 | 见评审第 5.7 节 | 不变 |

**不能声称的：** 首次只报告传播到输出的违例；首次处理多周期累积；首次与高精度或参考语义对照。

**可以尝试声称的（都需要原型验证）：**

- PLC 中正常模运算无处不在（A1 写法），需要按类型关系比较两份执行；
- 中间结果宽度和除零等行为随目标而变，判据必须绑定目标平台语义；
- 以扫描周期为单位的干预重放，用来在多个违例事件之间归因控制后果；
- 结果能在原生运行时上重放确认。

如果原型最终只能做到“返回值与高精度结果不同”，那它离安全顶会的核心贡献还很远，应及时调整。

## 5. 搜索侧：吸收 GPT 第一部分的诊断

搜索不是主贡献，但要能到达违例，并在“生成器 × 判定器”消融中单独评估：

- **用到违例边界的距离作为进展。** 违例谓词本身就给出了与目标相关的进展。例如 `x + 1 > 32767` 的距离就是 `32767 - x`，可以替换现在的 affinity 和数量级分桶，修掉“counter=20 和 counter=99 得分相同”的问题。
- **前缀保持。** 修改前缀后检查已建立的状态是否仍然成立；遇到复位、模式变化或覆盖写入时，旧的前缀证据失效。
- **先修的小问题。** `fuzzer/engine/src/mutations.rs` 的 `semantic_float_type_name` 把所有 64 位类型当成 LREAL。在 RuSTy 里 TIME、LINT、DATE 都是 64 位，所以 TIME 参数会收到 `1.0e308` 这类值。评审中 FILTER_I 的 `T=1.0e308` 输入很可能由此产生。

## 6. 评测

**数据划分：**

- 开发集：用于普查和设计规则的 OSCAT 部分，加上 7 个已知问题和普查候选。这些都是开发集真值，不能算作工具的新发现。
- 留出集：按函数家族和共享依赖从库中划出，规则冻结前不看。
- 外部项目：没有审计过的开源 ST 库与工程。

**判据验证集（10–20 个正负例）：** 正常模回绕（A1）、有害回绕、行为等价的两种写法、状态被覆盖、多个违例互相干扰、中间结果宽度带来的差异。每个都有人工标定的三层结论。

**搜索与判定分开：** 各工具生成的完整测试序列都交给同一个后果判定器；再做“生成器（SemantiST / ICSQuartz / AFL++）× 判定器（崩溃 / 违例 / 后果）”的组合；参考重放与干预重放的成本计入预算。

**研究问题：**

1. **RQ1 崩溃不能证明原生缺陷：** 按独立根因统计，区分已确认的伪影、无法复现和待定；我们自己 harness 的缺陷单列，不计入“现有流程”。
2. **RQ2 判据是否判对：** 三层各自的数量；在 A1 对照集和等价改写对上的误报与不一致；在开发集真值上的召回；在留出集上的表现。
3. **RQ3 搜索：** “生成器 × 判定器”组合下，按根因去重的第二、三层发现。
4. **RQ4 跨周期与归因：** 必要历史长度的分布；需要归因才能判对的多事件案例占多少；只做单周期判定会漏掉多少。
5. **RQ5 平台语义：** 只在所配置的目标语义下出现的案例；中间结果宽度规则消除的误报；原生重放成功率。
6. **RQ6 真实影响：** 留出集和外部项目中的第三层缺陷；维护者或厂商的确认；至少一个完成第 3.7 节完整证据链的应用级案例。
7. **RQ7 消融：** 分别去掉关系比较、干预归因、平台语义、搜索侧的进展度量。

统计方法沿用评审第 5.5 节：交错调度、每组 10 次以上、首次发现时间用生存分析、Mann–Whitney U 与 Â12。

**第 4 阶段关口按证据质量判断，不按数量：**

- **走顶会（NDSS / USENIX Security）**需要三个条件：
  - 第三层缺陷跨越多个函数家族或项目，而不是同一个模式的重复；
  - 至少一个案例完成原生平台上的完整安全证据链；
  - 干预归因或关系比较在消融中有清楚的贡献。
- **走 CCF-B**（首选 DSN，其次 ACSAC、RAID）：判据被验证有效，但真实影响或跨项目证据不足。
- **第 2 阶段就失败**：论文收缩为“保真度测量＋平台校准”投 CCF-B，同时启动 online change 的两周可行性验证。

建议第 3 周就写出引言和图 1，用写故事倒逼后续工作。

## 8. online change 放在哪里

它是比本文更“新”的问题，但不建议现在作为主线：没有证据，依赖真实版本对，与现有代码复用少，还要放弃已经在手的测量数据。以后做的话，要先处理三点：

1. **定义的出处。** Gupta、Jalote、Barua（IEEE TSE 22(2), 1996）提出了在线版本变更的形式框架，以状态可达性来定义更新是否有效；SCV 中 s' ∉ R_new 的定义与之基本同构。其中具体的定理（例如不可判定性）引用前要核对原文。新颖性要落在 PLC 特有的部分：厂商固定的迁移规则、扫描周期、补丁校验失效。
2. **要比较的前作。** 动态软件更新中的状态迁移函数研究；IEC 61499 动态重配置。
3. **“开发者没用好”的质疑。** 要用 IDE 不提示的比例来回应。

它的两周可行性验证成本低，可以在主线受阻时立即启动，也可以交给合作者并行做。

## 9. 对现有代码的影响

- **直接可用：** P0 修复后的 ABI 推导（参考构建的 harness 可直接生成）、违例谓词、`PersistentState`、在线去重与首次发现时间、统一重放分类。
- **需要修改：**
  - IntegerOverflow 谓词的判断点按目标平台的中间结果宽度调整；
  - 修复 `semantic_float_type_name` 把 64 位一律当 LREAL 的问题；
  - 用到违例边界的距离替换 affinity 型状态进度。
- **新增：** 平台配置及其差分测试、参考构建（第一版范围）、关系比较、干预重放、虚拟时钟、原生重放。
- **降级：** 路径搜索与五维 effort 公式、复杂的抽象状态遥测、快进、LLM。
